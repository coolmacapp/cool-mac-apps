# Editorial Guidelines

The GitHub list is a concise, practical reference to macOS software. Every listing should help someone understand what an app does before they click.

## Listing rules

- **One sentence, ideally 100–180 characters.** Longer is fine only if the app cannot be accurately described otherwise.
- **Factual and specific.** Name the core function and, where useful, one or two important capabilities.
- **Independent wording.** Do not paste an app's website tagline or promotional claims.
- **Neutral tone.** Avoid “best,” “ultimate,” “must-have,” and unsupported superlatives.
- **No unsupported testing claims.** Being listed does not mean the team has installed or tested the app.
- **No invented metadata.** Verify official links, availability, and features before adding them.
- **No third-party images.** App icons and screenshots are deliberately omitted from list entries.

## Structure

- Keep categories alphabetical.
- Include only categories with at least one listed app.
- Put each app under its **primary category** only.
- Sort app names alphabetically within each category.
- Use the app's name as plain bold text, not as another outbound link.
- Put the **Official website** link on the next line.
- An optional **Read more** link may point to a matching `https://coolmac.app/apps/<slug>` page. Omit it when no matching page exists; never invent or require a slug.

## Manual publishing checklist

1. Confirm that each app is publicly available and actively maintained.
2. Verify every included app has a working official website URL and, when included, a valid Cool Mac Apps **Read more** URL.
3. Write or review each one-sentence description independently.
4. Group each app under its primary category and keep categories alphabetical.
5. Sort each category A–Z, eliminate duplicates, and remove empty categories.
6. Update both the **Browse by category** table and **App directory** in `README.md`.
7. Check links and Markdown formatting in GitHub's preview before merging.

**Future automation is intentionally out of scope.** The README is edited directly for now; there are no scripts, scheduled tasks, or JSON description mirrors.
